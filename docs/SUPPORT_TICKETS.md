# Технические заявки из клубных бесед

Отдельный Telegram-бот не нужен. Команду и кнопки обслуживает существующий
`bot.admin_main` с токеном `CM_BONUS_BOT_TOKEN`.

## Настройка

1. Добавьте админского бота в техническую беседу.
2. Укажите ID беседы в `.env`:

   ```env
   TECH_SUPPORT_CHAT_ID=-1001234567890
   ```

   Если переменная не заполнена, используется `TECH_ALERT_CHAT_ID`.
3. У каждой клубной беседы должен быть свой `clubs.cm_bonus_admin_chat_id`.
4. Выполните миграцию и перезапустите `clubmodule-admin-bot.service`.

Проверка конфигурации без отправки сообщений:

```bash
venv/bin/python scripts/check_support_tickets.py
```

## Работа

- В клубной беседе: `/ticket текст обращения`.
- Команду можно отправить ответом на существующее текстовое сообщение, не
  дублируя текст после `/ticket`.
- Новая заявка получает статус `ожидание оператора`.
- В технической беседе доступны переходы:
  `Взять в работу` → `Пауза` / `Выполнено`; после паузы —
  `Продолжить` / `Выполнено`.
- Каждый переход сохраняется в `support_ticket_events`, а клубная беседа
  получает сообщение о новом статусе.

Нагрузка от пяти клубных бесед для текущего long-polling процесса мала. Причиной
для отдельного бота может быть только организационное разделение прав и чатов,
но не производительность.

## Безопасная проверка на stage

Stage unit `clubmodule-stage-admin-bot.service` содержит только локальное
разрешение `ALLOW_STAGE_ADMIN_BOT=1`. Оно позволяет запустить интерактивный
админский бот при наличии `.stage-no-outbound`, но не снимает общий запрет с
рассылок, опросов и фоновых обработчиков. Гостевой stage-бот остаётся
заблокированным общим стоп-файлом.

`support_tickets` и `support_ticket_events` сохраняются локально и не копируются
из production во время зеркалирования данных.
