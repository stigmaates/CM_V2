# Кейсы и задания в портрете гостя

Пересчёт: `scripts/rebuild_user_portrait.py`, отдельно по `(club_id, guest_id)`.
Изменение расширяет данные портрета; отдельная страница карточки гостя не добавляется.

## Кейсы

- `case_openings_count`: все открытия из `guest_case_openings`.
- `last_case_opening_date`: дата последнего открытия, UTC.
- `case_openings_by_case`: JSON-массив с `case_id`, `name`, `openings_count`,
  `last_opening_at` (ISO 8601 с UTC-смещением).
- Учитываются неактивные и удалённые кейсы. Если название удалено из справочника,
  выводится «Кейс #ID (удалён)». Название существующего кейса берётся текущее.

## Задания

- `missions_completed_count`: число зафиксированных выполнений за всю историю.
- `avg_missions_per_month`: количество выполнений / количество календарных месяцев
  от первого выполнения до текущего месяца включительно. Месяцы без выполнений
  учитываются, текущий неполный месяц считается одним. Границы месяцев — в зоне клуба.
  Например: первое выполнение в июле, всего 6 к сентябрю → 6 / 3 = 2.
- `last_mission_activity_date`: последнее зафиксированное выполнение (UTC).
- При отсутствии выполнений оба счётчика равны 0, дата — NULL.
- Среднее доступно в фильтрах рассылок. Существующий фильтр общего числа выполнений
  теперь получает реальные значения.

Источником служит `guest_mission_completions`, независимая от `club_missions` история.
При синхронизации заданий гостя сохраняется первое обнаруженное выполнение,
в том числе без награды. Повторное посещение кабинета не создаёт новое выполнение.
Идентичность соответствует текущей логике наград: один guest/club/mission_id — одно
выполнение. Новое задание с новым ID считается отдельно.

Миграция восстанавливает историю по положительным наградам типа `mission`
из журналов КБ (статус `done`) и жетонов. Две валюты за одно задание считаются один
раз, берётся ранняя дата начисления. Активность или наличие задания в справочнике
не проверяются. Историческая дата — дата начисления, новые даты — время фиксации
выполнения модулем, а не реконструкция момента достижения цели по сессиям.

Старые выполнения без сохранённой награды восстановить этим способом нельзя.
Сам пересчёт портрета не проверяет прогресс всех заданий всех гостей и не выдаёт награды.
Поле `missions_in_progress_count` этим изменением не затрагивается.

## Обновление stage

После получения нового кода сначала выполнить миграции, затем перезапустить web
и пересчитать портрет:

```bash
cd /root/cm_stage/CM_V2
venv/bin/python scripts/migrate.py
systemctl restart clubmodule-stage.service
venv/bin/python scripts/rebuild_user_portrait.py
```

Миграция восстанавливает только историю выполнений, не меняет балансы и не начисляет
награды. Перед production требуется проверить реальные данные на stage.
