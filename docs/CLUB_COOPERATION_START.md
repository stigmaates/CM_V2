# Начало сотрудничества с клубом

В админке `/admin/clubs` справа от «Обслуживание» добавлена сортируемая
колонка «Начало сотрудничества» в формате ДД.ММ.ГГГГ, в часовом поясе клуба.

Источник — время начала первой успешно завершённой initial-синхронизации
гостей. Оно хранится в `clubs.cooperation_started_at` в UTC. Запись выполняется
после сохранения гостей, как при запуске из админки, так и при запуске скрипта.
Повторные загрузки не сдвигают дату; при перекрывающихся запусках остаётся
самое раннее начало успешной загрузки. Ошибки и отключённые клубы дату не
устанавливают. Успешная загрузка пустого списка тоже считается синхронизацией.

Миграция `0025_club_cooperation_started_at` восстанавливает неизвестные даты
из самого раннего `admin_sync_logs.started_at` с `script_name = 'guests'`,
`sync_mode = 'initial'`, `status = 'success'`. Уже сохранённые даты не меняются.
Если старых логов нет (например, первоначальная загрузка выполнялась напрямую
до этого изменения), историческую дату восстановить нельзя: отображается «—».
Следующая успешная initial-загрузка установит первую известную дату. Даты
регистрации гостей в LG не используются.

При выкладке: применить миграции через `venv/bin/python scripts/migrate.py`
до запуска новой initial-синхронизации, затем перезапустить веб-сервис
соответствующего окружения. Код не выкладывается автоматически.

Проверки: `tests/test_club_cooperation_start.py` — восстановление дат,
повторная миграция, повторные/перекрывающиеся запуски, ошибки, отключённый клуб,
часовой пояс и рендер таблицы. SQL проверяется локально на SQLite с адаптацией
плейсхолдеров и LEAST; миграцию на MySQL следует проверить на стейдже.
